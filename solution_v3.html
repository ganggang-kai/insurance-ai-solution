一、项目概述

本项目旨在构建一套「画布编排筛意向 + Agentic AI自主引导投保」的混合智能转化体系。 开场白与意向筛选阶段采用流程画布实现（合规可控），意向客户确认后进入Agentic模式——由LLM回复节点自主与客户对话， 通过Tool调用完成专属码获取等关键动作，逐阶段引导客户在微信公众号内完成投保全流程。

产品定位：0.6元短期意外险（首单）+ 复购升级产品，无健康告知，仅支持银行卡签约快捷支付。

2.3 子流程内部运行机制

🔄 LLM回复节点工作模式

每个子流程内部由一个LLM回复节点驱动，运行逻辑如下：

  • 回复意图 → LLM继续与客户对话，引导完成当前阶段目标（如引导关注公众号、引导输入专属码等）
  • 退出意图 → LLM判断当前阶段目标已达成，触发退出，画布跳转至下一子流程
  • Tool调用 → 对话过程中LLM按需调用Tool（如获取专属码），将结果融入对话

三、核心业务流程

全链路共9个阶段，前2阶段由流程画布驱动，后7阶段由Agentic LLM自主引导：

流程画布 Agentic LLM回复节点

  1. 📞 开场白 + 意向筛选 流程画布

    AI外呼开场说明来意，建立信任。LLM分类节点识别客户意向，非意向客户礼貌结束，意向客户进入Agentic阶段。

  2. 📲 引导关注公众号 LLM回复节点

    LLM自主引导客户搜索并关注公众号。根据客户反馈灵活调整话术（如客户说找不到→换关键词引导，客户说已关注→确认后推进）。

  3. 🎯 引导进入专属码输入入口 LLM回复节点

    引导客户在公众号找到指定入口。LLM根据客户描述判断是否已到达正确页面，灵活纠偏。

  4. 🔑 输入专属码 LLM回复节点 + Tool

    LLM调用「专属码获取」Tool拿到客户专属码并口播。引导客户输入后确认手机号反显成功。

  5. 📝 填写个人信息并点击按钮 LLM回复节点

    引导客户填写姓名、身份证号并点击确认按钮。LLM根据客户反馈判断是否完成。

  6. 💳 收银台输入验证码并签约快捷支付 LLM回复节点

    引导客户在收银台页面输入银行卡验证码，完成快捷支付签约并扣款0.6元。

  7. 🔄 第二次点击投保按钮 LLM回复节点

    首单完成后引导客户点击升级产品的投保按钮，进入复购流程。

  8. 💰 第二次扣款并完成升级 LLM回复节点

    引导客户确认复购产品信息并完成第二次扣款，签约快捷支付自动扣款无需再输验证码。

  9. 🏁 投保完成 → 结束挂机 LLM回复节点

    确认投保成功，告知保障生效时间和权益，礼貌结束通话。

六、方案优势与落地要点

6.1 混合架构优势

🛡️

开场合规可控

开场白与意向筛选由画布固定话术实现，零Token成本，100%合规可控，不会出现LLM"胡说"风险。

🧠

后续灵活应对

投保引导阶段由LLM自主对话，可灵活应对客户千变万化的问题和操作情况，无需为每种分支预设节点。

📉

节点大幅精简

原纯画布方案需30+节点、40+分支逐一编排。混合方案画布仅需编排主流程骨架，复杂对话逻辑交由LLM处理。

🚀

分阶段快速上线

Demo阶段仅对接专属码API即可跑通全流程，快速验证效果。POC阶段渐进增加Tool能力，降低启动门槛。

6.2 落地要点

要点说明
子流程Prompt设计每个子流程需精确定义阶段目标、退出条件、异常兜底策略。Prompt质量直接决定对话效果
退出意图准确性LLM需准确判断当前阶段是否完成，避免过早跳转（客户实际未完成）或迟迟不跳转（客户已完成但AI还在引导）
响应延时控制LLM回复节点需保持低延时响应（<2秒），避免客户等待过长。选用推理速度快的模型或对话场景做专项优化
Tool调用稳定性专属码获取等Tool需保证接口稳定和响应速度，Tool调用失败时LLM需有兜底话术
上下文窗口管理子流程切换时可重置上下文，每个子流程仅保留当前阶段相关信息，避免长对话导致的上下文溢出
